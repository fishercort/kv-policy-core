# Telemetry Compute conformance fixtures (v0)

Golden fixtures for the telemetry event model (`docs/telemetry-event-model.md`). Any
implementation that consumes the normalized events and computes residual/eviction detection +
catalog stats must reproduce each fixture's `expect` given its `config` and `events`. This is
the language-neutral contract: the Python reference and the Rust agent test against the same
files.

## Fixture format
```
{ fixture_version, salt, provenance,
  name, config: {block_size, evicted_cap?},
  events: [ {source, type, ts, block_hash?, block_size?, parent_hash?, medium?} ... ],
  expect: { residual_tokens, eviction_recompute_tokens, catalog_peak_entries,
            evicted_aged_out, record_counts, records: [...] } }
```
`type` is one of `StoredBlock` / `RemovedBlock` / `ClearedAll`. Events are ingested in array
order (already in global timestamp order).

## Salting (must match exactly)
A record's `block_id` is `sha256(salt || 0x00 || domain || 0x00 || decimal(block_hash))[:16]`,
hex. `domain` is `"default"`. Block hashes in fixtures are integers, and `decimal(int)` is
language-neutral, so an implementation reproduces the ids byte-for-byte.

## Scope
The OPEN-module contract only: normalization, resident/evicted tracking, residual and eviction
*detection*, catalog stats, metadata-only records. Dollarization / band economics are not part
of this contract.
